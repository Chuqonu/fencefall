# Fencefall v2 平衡实测 / Balance verification

## 复现

```sh
npm test
node scripts/balance.mjs --seed-count=10 --verify --output=acceptance
npm run build
```

每个场景复用同一组种子 11、42、73、104、135、166、197、228、259、290。完整矩阵共有 400 局，包括 180 局主线和 220 局短出击。每局都运行发布版引擎的固定 1/60 秒步进，并执行实际选牌、放塔、合成、消耗辉光、建工事和索敌操作。策略的随机选择使用独立 RNG。每个种子的原始记录写入 `artifacts/acceptance.json`，该目录由 Git 忽略。`--verify` 会在任一硬指标失败时返回非零。

## 策略与计量

| 策略 | 决策 |
| --- | --- |
| aggressive | 优先火、雷、穿钉，补中路墙和地刺，优先能立即合成的牌。 |
| hybrid_econ | 前六次整备争取一座后排辉穗，用额外收益补前线、重随和合成。 |
| control | 优先霜、雷与控制，布置显隐灯塔，并给新攻击塔选择高危优先。 |
| random | 均匀随机选牌与空格，不造工事、不重随、不主动寻找合成。 |
| mono | 使用前线与同型升阶，禁用混合配方。 |
| solo | 只接受英雄升级。若三张都是塔，测试程序跳过该次机会，不返还 XP、不授予其他资源。全程无塔、无工事。 |

三种结构化策略都根据当前英雄击杀比例选择后续升级及索敌，可合成时优先增加阶数和混合收益。所有基线局都从零装备、零永久成长开始。Hard 装备组佩戴棱镜核心、奔行护符、脉冲电容，四条永久成长均为 4/5 级。

每一模拟秒采样一次屏内（敌人中心位于出生线至栅栏可见区域）活敌数，再求各局中位数和峰值。空场占比按无活敌的固定步数除以总战斗步数。沿用原测试的停滞规则，场上有活敌且连续 3 秒既未对敌造成伤害也未扣栅栏血量时，开始累计停滞时间。全局累计超过 20 秒记一次警报。英雄击杀占比按实际归属英雄的击杀事件数除以总击杀数。选择卡牌和暂停耗费的现实时间不计入胜利时长。

## 混合塔与前端对接

静态参考场景包含带甲前排、后方相邻目标和附近三名盟友。基础塔与混合塔共用同一评分函数，计入直接火力、暴击、穿透、群伤、持续伤害、控制、显隐、光环和后排射程。15 个配方的断言分别比较实际合成后的一级单位与双亲本，要求比值至少 1.25。最低为烽坛（pyre）约 1.446。该值是场景功能分，单体木桩 DPS 和任意阵容的实战伤害会不同。具体权重在 `tests/encounter-power.mjs` 中。

核心系统生成事件，`src/boot.js` 每帧通过 `takeEvents()` 取出后分发。新增视觉和音效应消费同一批事件，避免第二次排空队列。弹道用 shot 的起点、目标坐标与标签，命中特效用 hit 的反应与护甲信息，地面持续效果读取带 ID 的 clouds。防线护盾持续时长取 surge.shieldTimer。工事通过 index 和 kind 对应画布位置。完整字段见 REFACTOR_SPEC.md §8.3。表现层使用独立的时间与随机源，避免改变固定步进和战斗 RNG。
